# CPC6128 — status implementacji

Zastępuje `2026-09-16-cpc6128-integration-plan.md` i
`2026-09-16-cpc6128-remaining-work-plan.md` (skonsolidowane, oba plany
wykonane). Otwarte punkty patrz `2026-09-16-open-items.md`.

## Zaimplementowane i zweryfikowane

- `src/PetEmulator.Cpc6128/` — `Cpc6128Machine : IMachine`, RAM 128 KB,
  bankowanie 0-7, `Cpc6128MemoryBus`, `Cpc6128Ports`.
- `lib/PetEmulator.CpcFdc/` — `I8272Chip`, `DskDiskImage`/`DskFloppyDrive`,
  osobny projekt, nie miesza z FD1791/FD1793 (Kaypro/TRS-80).
- ROM fixture: `roms/cpc6128/cpc6128.rom` (32 KB, SHA-256
  `31c3668c67bea027dab698ece233c9434d9324f9ba7dac84db58f400b6689562`),
  `roms/cpc6128/amsdos.rom` (16 KB, SHA-256
  `ea65e0fb44ee93ede4b6c507509b7e5ddf497fb7155023bea91ef229469fa04d`).
- `tests/PetEmulator.Cpc6128.Tests/Cpc6128BootTests.cs` — realny ROM bootuje
  do `Ready`, `PRINT 1+1` przechodzi przez firmware.
- `tests/PetEmulator.Cpc6128.Tests/Cpc6128Cpm22BootTests.cs` — realny DSK
  (`roms/cpc6128/6128SP_4.DSK`, CP/M 2.2, źródło `personal-002`, SHA-256
  w `roms/cpc6128/README.md`) bootuje do `A>` przez AMSDOS. Pokrywa
  `|CPM`/odczyt DSK przez firmware z kryteriów zakończenia poniżej.
- `src/PetEmulator.Cli/Cpc6128DebuggerSession.cs` — `cpc6128-debug` CLI,
  komendy `roms`/`tape`/`disk`/`key`/`status` + wspólny `MachineDebugger`.
- Desktop: `Cpc6128MachineViewModel`, `Cpc6128MachineView.axaml`, wpis w
  menu, `IDatasetteViewModel` + `IDiskDriveViewModel`.
- Snapshot/debug (M8): `CaptureState`/`RestoreState` na FDC (reużyty
  `I8272Snapshot`), `Cpc6128MemoryBus`, `CpcGateArray`, `MT6545`, `Ay38910`,
  `CpcKeyboard`, `CpcCassette`, `Cpc6128Ports`; agregat `Cpc6128Snapshot`
  (dziedziczy po wspólnym `CpcMachineSnapshot`/`MachineSnapshot`, patrz
  `2026-09-16-cpc-architecture.md`); `Cpc6128SnapshotCodec` (System.Text.Json,
  walidacja wersji). Testy: round-trip na nowej instancji maszyny (nie tej
  samej), round-trip z zamontowanym dyskiem.
- Dokumentacja: `docs/chips/I8272.md` + wpis w `docs/chips/README.md`,
  `docs/desktop/multi-machine.md` opisuje capability CPC6128.
- Testy: `[Category("BinaryBoot")]` sformalizowane jako opt-in
  (`AGENTS.md`), domyślny `dotnet test PetEmulator.slnx --filter
  "TestCategory!=BinaryBoot"` zielony na całym solution.

      I/O/audio i FDC/media;

      przez AMSDOS przechodzą przez rzeczywistą ścieżkę firmware;

      granicach;
- [x] audio AY podłączone przez `IAudioOutput`, kaseta i dysk dostępne z
      Desktop przez capability interfaces;
- [x] snapshot przywraca stan CPU, pełne 128 KB RAM, porty, urządzenia i
      transfer FDC (w tym mid-transfer, dzięki polom `I8272Snapshot`);
- Nie deklarować pełnej zgodności CPC6128 na podstawie samego ekranu
  `Ready` — zachowane: `Ready`, `PRINT 1+1` i CP/M boot to trzy niezależne
  ścieżki firmware, nie jedna.
