# FD1793 / WD179x — kontroler dyskietek

`FD1793` jest klasą potomną `FD1791`; wspólny model poleceń, rejestrów,
transferów i błędów znajduje się w `FD1791`, a wariant 1793 deklaruje
magistralę DAL typu `True`. Układ jest
niezależny od konkretnej mapy portów lub adresów pamięci: maszyna mapuje
rejestry `Read(byte)`/`Write(byte)` według własnego schematu sprzętowego.

Kontrakt wspólnego rdzenia i różnice polaryzacji opisuje [`FD1791.md`](FD1791.md).

Implementacja znajduje się w:

- `lib/PetEmulator.Chips/FD1791.cs`
- `lib/PetEmulator.Chips/FD1793.cs`
- `lib/PetEmulator.Chips/IFD1793DiskImage.cs`
- `tests/PetEmulator.Chips.Tests/FD1793Tests.cs`

## Rejestry

| Offset | Odczyt | Zapis |
| ---: | --- | --- |
| `$00` | status | command |
| `$01` | track | track |
| `$02` | sector | sector |
| `$03` | data | data |

Wybór napędu jest osobnym zatrzaskiem `DriveSelect`, ponieważ jego adres i
mapowanie bitów zależą od płyty komputera.

### Type I — pozycjonowanie głowicy

- [x] `RESTORE` — powrót na ścieżkę 0.
- [x] `SEEK` — cel pobierany z rejestru data.
- [x] `STEP`.
- [x] `STEP IN`.
- [x] `STEP OUT`.
- [x] `STEP` powtarza ostatni kierunek `STEP IN`/`STEP OUT`.
- [x] Raportowanie `TRACK 00`.
- [x] Reset indeksu adresów po zmianie ścieżki.
- [x] Timing komend pozycjonowania.

### Type II/III — transfery

- [x] `READ SECTOR`.
- [x] `WRITE SECTOR`.
- [x] `READ ADDRESS`.
- [x] Sektory 128, 256, 512 i 1024 bajty.
- [x] `DRQ` dla każdego bajtu transferu.
- [x] Deadline transferu i `LOST DATA`.
- [x] `RECORD NOT FOUND` dla brakującego sektora.
- [x] `WRITE PROTECT` dla zapisu na zabezpieczonym obrazie.
- [x] Transfery wielosektorowe przez bit multi-record.
- [x] Raportowanie numeru ścieżki, strony, sektora i kodu rozmiaru przez `READ ADDRESS`.
- [x] Raportowanie deleted data mark przez `RECORD TYPE`.
- [x] Obsługa jednostronnych i dwustronnych obrazów.
- [x] Kontrola zgodności gęstości obrazu z trybem kontrolera.

### Type IV i sygnały sprzętowe

- [x] `FORCE INTERRUPT` anuluje aktywną komendę.
- [x] `INTRQ` po zakończeniu komendy, błędzie i anulowaniu.
- [x] `DRQ` podczas transferu danych.
- [x] Linie WAIT są poza kontrolerem i są obsługiwane przez `KayproFdcWiring`.
- [x] Konfigurowalny timing seek, komendy sektorowej, bajtu i indeksu.

## Świadomie poza zakresem

- [ ] Surowy strumień flux i analogowy separator danych.
- [ ] Błędy CRC liczone z bitów zapisanych na nośniku.
- [ ] Fizyczny silnik, prędkość obrotowa i mechanika głowicy poza modelowanym timingiem.
- [ ] Automatyczne mapowanie rejestrów do konkretnego komputera.
- [ ] Pełny model kontrolera PIO/napędu Kaypro — należy dodać w warstwie maszyny.

Obrazy dysków dostarczane przez maszynę muszą jasno określić geometrię,
rozmiar sektora, numerację pierwszego sektora, gęstość oraz zachowanie zapisu.
