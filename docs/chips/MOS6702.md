# MOS6702

## 8.9 `MOS6702` — dongle ochrony SuperPET

Plik: `lib/PetEmulator.Chips/MOS6702.cs`.

MOS 6702 jest nieudokumentowanym firmowym układem ochrony używanym w
SuperPET/SP9000. Jego model emulatora opiera się na funkcjonalnym opisie
reverse-engineeringu oraz implementacji VICE, a nie na oficjalnym datasheet.

## Mapa adresowa

- [x] Mapowanie `$EFE0-$EFE3` w mapie 6809 SuperPET.
- [x] Wszystkie cztery adresy są aliasami jednego rejestru danych układu.
- [x] Odczyt zwraca bieżący stan ośmiu flip-flopów wyjściowych.
- [x] Zapis przekazuje bajt do sekwencji wejściowej dongla.
- [x] Dostęp spoza zakresu zgłasza `ArgumentOutOfRangeException` w modelu układu.
- [x] Potwierdzić kombinację linii CS na podstawie schematu `324055.gif`:
      `CS0=1`, `CS1=1`, `CS2=1`, `CS3=1` oraz aktywne niskim stanem
      `CS4#=0`, `CS5#=0`, `CS6#=0` wybierają układ.
- [x] Uwzględnić dekoder `74LS138` U1 i jego wyjście `Y7/K10*` jako część
      board-level dekodowania wyboru SuperPET.
- [x] Potwierdzić, że dekodowanie płyty udostępnia dongle jako cztery aliasy
      `$EFE0-$EFE3`; nie są to cztery równocześnie adresowane układy.

## Stan wewnętrzny

- [x] Input Register — bieżący bajt wejściowy zapisu.
- [x] Even/Odd Register — oczekiwanie na właściwą parzystość bitu 0.
- [x] Last Number Register — poprzedni zaakceptowany bajt nieparzysty.
- [x] Osiem circular shift registerów o długościach:
      `6, 3, 7, 8, 1, 3, 5, 2` dla bitów `0..7`.
- [x] Osiem flip-flopów wyjściowych.
- [x] Stan resetowy wyjścia i poprzedniej wartości: `$D6`.
- [x] Stan oczekiwania po resecie: pierwszy zaakceptowany zapis musi być parzysty,
      a dopiero następny nieparzysty może zmienić wynik.

## Algorytm zapisu

- [x] Zapis o niewłaściwej parzystości jest ignorowany i tylko przełącza fazę,
      gdy tworzy poprawną parę even→odd.
- [x] Dla zaakceptowanego bajtu obliczane jest `LastAccepted XOR Input`.
- [x] Zmienione bity modyfikują pozycję odpowiednich rejestrów kołowych.
- [x] Rejestry są przesuwane o jedną pozycję z zawijaniem.
- [x] Bit wysuwany z każdego rejestru przełącza odpowiedni flip-flop wyjściowy.
- [x] Zaakceptowany bajt staje się wartością porównywaną przy kolejnej sekwencji.
- [x] Zapis odd bez poprzedzającego even oraz powtórny zapis tej samej fazy
      nie zmienia wyjścia.

## Integracja z SuperPET

- [x] Utworzyć `MOS6702` jako osobny układ implementujący
      `IMemoryMappedDevice`.
- [x] Podłączyć układ wyłącznie do mapy procesora 6809; mapa 6502 pozostaje
      mapą standardowego PET.
- [x] Reset `PetMachine` resetuje dongle razem z pozostałymi urządzeniami.
- [x] Udostępnić układ przez `PetMachine.SuperPetProtectionDongle` dla diagnostyki.
- [x] Obsłużyć warianty z innymi wartościami inicjalnymi lub długościami rejestrów
      przez `MOS6702Variant`; wariant standardowy pozostaje zgodny z VICE.
- [x] Zweryfikować bieżący zestaw trzech Waterloo ROM-ów: nie zawiera on
      osobnego wyboru drugiego dongla, a mapa SuperPET udostępnia jeden aktywny
      układ przez cztery aliasy. Nie jest to jeszcze dowód dla nieznanych wersji
      firmware.

## Ograniczenia i źródła

Model odwzorowuje standardowy aktywny dongle SuperPET. Oryginalna płyta miała
gniazda na cztery warianty 6702, ale dokumentacja nie definiuje ich jako czterech
niezależnych adresów magistrali; dlatego emulator nie udaje równoczesnego
mapowania czterech różnych układów.

Nie ma w repozytorium osobnego obrazu programu diagnostycznego SuperPET, dlatego
test bit-perfect pełnego programu pozostaje otwarty. Dostępny test integracyjny
uruchamia rzeczywisty Waterloo ROM przez wektor resetu i sprawdza mapę jednego
dongla; nie zastępuje on pełnego diagnostyku sprzętowego.
